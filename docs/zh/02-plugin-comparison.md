## 一、先看懂三条技术路线

"让 DeepSeek 看视频"在工程上只有三条路，选插件本质是选走哪条路：

| 路线 | 原理 | 成本 | 信息损失 | 适用 |
|---|---|---|---|---|
| **A. 字幕文本** | 抓 B 站官方/AI 字幕 → 纯文本给模型 | 最低（几万字符 ≈ 几千 token） | 丢失画面、语气、板书 | 口播型课程（占网课大多数） |
| **B. 语音转写** | 下载音轨 → 本地 faster-whisper / 云端 ASR → 文本 | 中（本地吃 CPU/GPU，云端按分钟计费） | 同上 + 识别错字 | 无字幕的老课程、录屏 |
| **C. 视觉/OCR** | 抽帧 → 拼宫格图给视觉模型，或 OCR 成文字 | 最高（图片 token 是文本的 10~100 倍） | 依赖采样率，会漏短暂画面 | PPT、板书、代码演示 |

> ⚠️ **2026-11-13 实测修正**：本节原来依据 `dsh-video-understand` 的 README，断言
> "DeepSeek 是纯文本、看画面只能靠 OCR"。**实测推翻了这个前提**：
> 当前 DSH 配置下模型能直接消费图片附件（能读出手写板书里的代码和颜色标注）。
> 所以路线 C 的两条出口都通，且**"看图"明显优于"OCR"**——实测 OCR 把
> `a=a+10` 认成 `a=a+lo`、`a+=5` 认成 `a=ats`，而看图全部读对。
>
> 结论改为：**A（字幕）打底，C（看图）补关键帧；OCR 只在没有视觉能力时兜底。**
> 细节见 [05](05-verification-log.md) 第四节、[06](06-timestamp-code-and-notes.md)。

**对本机的现实结论（环境已在第二轮配好）**：A 与 C 都能走。
`ffmpeg` 在 PATH，`bili-frame.ps1` 已实测；插件装上即可补齐字幕与搜索。

## 三、逐个说清楚（含坑）

### 3.1 `dsh-bili-watch` —— 本机条件下的最优解 ★★★★★

**它做什么**：把一条 B 站链接变成"模型能直接吃"的结构化内容。14 个 CLI 命令，覆盖从元数据到画面 OCR 的全链路。

```
view      元数据 + 简介 + 热评（不下载，匿名可用）
sub       官方 AI 字幕，可导出 srt/json/md/txt
comments  评论区（含楼中楼）
danmaku   弹幕热区（按时间桶统计峰值）
asr       本地 faster-whisper 转写 + 可信度判定
frames    抽帧（--scene 按画面变化点抽，更准更省）
ocr       抽帧并识别画面文字
text      四级降级链：字幕 → 转写 → 抽帧OCR → 读图
sheet     九宫格拼图（--cues 每格下方附台词）
peek      元数据 + 热评 + 5 帧（走官方截帧接口，不下视频）
search    站内搜索（可按天数过滤、按播放排序）
hot       热门榜
login     扫码登录
clean     清缓存
```

**为什么推荐它**：
1. **核心能力零依赖**——元数据/评论/弹幕/搜索/字幕全都只走 HTTP，不需要 ffmpeg、不需要 Python。这正好卡在本机现状上。
2. **输出为 AI 设计**：自带 `[mm:ss]` 时间码，长文本超过 800 字自动落盘只回摘要，模型用 `read` 分段读——**不炸上下文**。
3. **有防幻觉机制**（这点对学习极重要）：ASR 输出附「可信 / 疑似幻觉」判定；字幕语速异常（<2 或 >8.5 字/秒）会判定可疑；可用 `--verify` 抽 5 帧 OCR 交叉核对。
4. **MIT + 文档 400 行**，连"缓存目录哪些子目录能删"都写清楚了，是我见过最认真的一个。
5. 有 Web 面板：依赖状态、扫码登录、缓存管理、18 项运行时参数。

**坑**：
- AI 字幕要登录（`SESSDATA`）。匿名只能拿到部分。
- 只读，不点赞不评论（对学习场景反而正确）。
- `bili_watch` 工具名如果和别的插件冲突，后注册的覆盖先注册的。
- 需要 Node ≥ 22（本机 v24 ✅）。

**安装**：`dsh plugin --profile web add dsh-bili-watch`

### 3.2 `dsh-bili-study` —— 学习管理，不是视频理解 ★★★★☆

**它做什么**：侧栏多一个「B 站学习台」。把 UP 主主页 / 收藏夹 / 单视频收进「科目 → 章 → 主题」，
用 B 站官方嵌入播放器看，右边记 Markdown + KaTeX 笔记，AI 帮你概念速查、生成知识图谱、补前置知识。

**优点**：
- **纯 JS，零外部依赖，不下载视频、不登录、不碰视频流** —— 本机可以直接装，装完就能用。
- 数据全在本机，`~/.dsh/bili-study/state.json`。
- 笔记支持公式（`$...$` / `$$...$$`），可导出。对理工科网课很关键。
- 「AI 前置连线」能生成主题之间的先修关系，适合搭学习路径。

**明确短板**：
- **AI 看不到视频内容**。它只知道标题。你问"这节讲了什么"，它答不上来。
- 它的 `bili_study_fetch` 只抓标题/元数据，不抓字幕。

**所以它不是"看视频"插件，是"课程管理 + 笔记"插件**。和 `dsh-bili-watch` 是互补，不是替代。

**安装**：`dsh plugin --profile web add dsh-bili-study`

---

### 3.3 `dsh-bili-eyes` —— 最"像人"的看视频体验 ★★★☆☆

**它做什么**：分镜图（每格 6~16 格、格号烧在图上、带时间和台词）+ B站上下文（AI 总结/热评/弹幕高频词/最密集时段）+ 逛站 + 互动。

**亮点**：
- 长视频不硬塞一张图，按「每格约一分钟」给 2~4 张；
- ffmpeg 可以在**设置页一键下载**（对本机这种没 ffmpeg 的环境很友好）；
- 写操作默认全关，按「对谁」分档（自己人/主人评论区/外人），权限设计非常克制；
- 台词来源：B站 AI 字幕 → 语音识别（硅基流动或本机服务）。

**短板**：
- 分镜图要**模型能看图**。DeepSeek 默认不能 → 你只能拿到图路径 + 文字，图片白抽。
- 功能重心其实在"逛 B 站 + 互动 + 群聊场景"，学习用途是附带的。
- 需要 B 站账号才能拿到 AI 字幕和 1080P。

**适合**：你同时配了多模态模型，或者想让它顺便帮你盯评论区/找相关视频。

**安装**：`dsh plugin --profile web add dsh-bili-eyes`

---

### 3.4 `dsh-bili-video` —— 全功能缝合怪 ★★☆☆☆

**它是什么**：两个人作品的合并改造版——`dsh-bili-subagent`（读嘴）+ `dsh-video-storyboard`（看眼）。
作者原话："这是我给自己用的小工具，顺手放上来给朋友抄作业。不是产品。"

**能力**：11 个 `bili_*` 工具 + 5 个 `video_*` 工具（`video_probe` / `video_storyboard` / `video_zoom` / `video_locate` / `video_watch`）。

**为什么只给两星（对本机）**：
- **Python 3.10+ 是硬依赖**（B站那半边必需），本机没有；
- **ffmpeg 是硬依赖**（看视频那半边必需）；
- 需要扫码登录；
- 作者明确不承诺维护。

**但它有两个独家优点**：
- `video_locate`：给一句话，找回它在片子里的大致时间码 —— **对"我记得老师讲过某个点但忘了在哪"极有用**；
- `video_zoom`：只在某个时间窗内重扫高清帧 —— 精看板书。

如果你愿意折腾环境，它的工具设计是这批里最贴合"反复回看"这个学习动作的。

---

### 3.5 `dsh-bili-vision` —— 为"多模态精读"设计 ★★★☆☆

**它做什么**：`inspect` 在本地整理证据（带真实时间戳的画面 + 官方字幕/本地转写 + OCR）交给**当前**视觉模型；
`run` 用独立视觉模型分析（主模型不能看图时用）。

**设计上最讲究的一个**：
- 2 fps 灰度帧算变化，候选帧按时间覆盖全片，默认最多 12 帧、四宫格；
- **只删除完全相同的画面**（比较完整 RGB，不用有损相似度阈值）；
- **OCR 结果真正进入证据**，不是摆设；
- 预算控制：默认文本预算 12000 token，标注省略数量，可指定时间范围续读；
- 26 项 Python 测试 + 7 项 Node 测试。

**短板**：Python 3.10+、ffmpeg、ffprobe 全要，且**没发布到 npm**，只能 `git+` 装。
`inspect` 还要求当前对话模型支持图片——DeepSeek 不行，得靠 `run` 配独立视觉模型。

---

### 3.6 `dsh-video-understand` —— 最省钱的理解方案 ★★★☆☆

**思路独特**：不做视觉，做"**信息层**"——ASR 转写 + 场景结构 + 运动对象轨迹 + YOLO 语义，
压缩成约 1k token 再喂 LLM。自称 token 压缩 99.95%+。

**优点**：
- 首次调用自动建隔离 venv（优先 uv，回退 pip 清华镜像），**不污染系统 Python**；
- 带 `doctor --fix` 一键自检修复；
- 有成本预算闸门 `budgetCny`，超预算自动降级；
- 支持 `questions` 数组一次问多个问题。

**短板**：
- 仍要 **ffmpeg**；
- 默认走小米 MiMo API（`LLM_API_KEY`），不是 DeepSeek 原生；
- 语义层（torch/YOLO）约 2 GB，除非你要"谁在什么位置做了什么"这种信息，否则用不上。

**适合**：你有一批视频要批量问答（"这门课讲了哪些算法"），且在意成本。

---

### 3.7 `dsh-video-coursemap` —— 想法很好，但被"无字幕"卡脖子 ★★☆☆☆

**它做什么**：每 15 秒读一次 Windows 前台窗口标题 → 判断你在看课程 → 自动抓字幕/弹幕/热评 → 提炼 8~20 条知识点 + Mermaid 思维导图 → 追加到对应学科的 Word《学习手册》。

**优点**：完全被动、零操作、零运行时依赖（纯 Node，不用 ffmpeg，不用下视频），按学科自动归档。

**致命短板**（README 自己承认）：
- "多数 B 站视频无机器字幕（subtitle 为空），字幕是尽力抓取、失败静默降级" → 降级后就只剩标题，等于没总结；
- 匿名评论接口封顶 3 条；
- AI 总结接口返回 -403 需登录，不可用；
- 前台窗口必须是浏览器/视频客户端，后台播放不触发。

**结论**：思路对（把学习记录自动化），但**依赖的字幕覆盖率不够**，现在装它大概率生成一堆"仅标题"的空手册。等它支持本地 ASR 再说。

---

### 3.8 `dsh-bili-summary` —— 极简纯 Node ★★★☆☆

**它做什么**：一个工具 `bili_summary`，一次调用拿回元数据 + 字幕时间轴 + 可选配图（sharp 从播放器快照接口切帧）。

**优点**：
- **纯 Node，无 shell 调用、无编码坑**，专治 Windows 文件名非法字符；
- 错误码映射完整（-404/-412/-352/62002），指数退避重试，风控自动重试；
- 字幕过长自动落盘 + 内联摘录；
- `withImages` 默认 false，不会乱花图片 token。

**短板**：
- 字幕走遗留 `view`/`player/v2` 接口，**没实现 WBI 签名**，B 站一收紧就失效（README 明说）；
- 未发布 npm，只能 `github:` 装；
- 图片依赖 sharp，node-gyp 在 Windows 上可能要编译。

**适合**：只想要"链接进、笔记出"的最小闭环，不想装一堆东西。

---

### 3.9 `dsh-bili-subagent` —— 批量预习用 ★★☆☆☆

**它做什么**：派一个子代理去刷 B 站，读字幕、翻评论，挑出值得看的，交回一份带笔记和卡片墙的内部报告。

**为什么放进来**：它报告里带**每条视频的笔记**，可以当"批量了解一个领域有哪些好课"的工具。
它的"两道硬门槛"（最低播放量、至少发布几天）在筛选课程时确实有用。

**短板**：
- Python 3.10+ 或 uv **必需**（要建 venv 装 `bilibili-api-python`）；
- **必须扫码登录**；
- 定位是"刷站 + 社交投递"，学习是副产品；
- 设置项极多（投递方式、评论配额、自动刷时段），学习场景大部分用不上。

## 五、最终选型

### 主推组合

```
必装：dsh-bili-watch      ← 把课变成带时间码的文字（学习的信息入口）
必装：dsh-bili-study      ← 把课管起来、记笔记、查概念（学习的组织层）
选装：dsh-web-studyhub    ← 把笔记变成闪卡、按 FSRS-6 复习（学习的记忆层）
```

三者职责完全不重叠：

```
dsh-bili-watch  →  产出：字幕文本 / 总结 / 考点
dsh-bili-study  →  承载：目录、笔记、进度、知识图谱
dsh-web-studyhub→  巩固：闪卡、测验、间隔复习
```

### 决策树

```
你主要想解决什么？
├─ "我看完课记不住 / 不会整理"      → dsh-bili-study + dsh-web-studyhub
├─ "我想要课程的文字稿和总结"        → dsh-bili-watch（+ 补 ffmpeg 拿板书 OCR）
├─ "我想让 AI 陪我精读某几节课"      → dsh-bili-watch 出文本 + 对话里追问
├─ "我想自动记录我看了什么课"        → 暂不推荐（coursemap 被字幕覆盖率卡住）
├─ "我想批量发现好课"                → dsh-bili-watch 的 search + hot 就够；真要自动化再说
└─ "我想让 AI 真的看懂板书画面"      → 需先有多模态模型；再上 dsh-bili-vision 或 dsh-bili-eyes
```

### 明确不推荐（对你现在的需求）

| 插件 | 不推荐的理由 |
|---|---|
| `dsh-bili-scroll` / `dsh-bili-whale` / `dsh-bili-pond` / `dsh-fish` | 娱乐向"养鱼/刷站"，帮你发现内容，不帮你学会内容；还会往你号上发评论 |
| `dsh-bili-jar` / `dsh-bili-merlin` | 同上，兴趣推荐向 |
| `dsh-bili-live` / `dsh-bili-danmaku-lite` | 直播场景，与网课无关 |
| `dsh-bili-humanism` | 人格训练向，偏实验 |
