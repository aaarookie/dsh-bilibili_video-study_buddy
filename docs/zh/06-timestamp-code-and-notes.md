## 四、四个必须注意的坑（都是实测踩出来的）

### 4.1 多 P 视频：时间点属于「某个 P」，不是整条视频

这是最容易错的一点。我实测的那门课：

```
总时长 5943s（99 分钟）  ← 这是 8 个 P 加起来
P1  626s   数据类型和输入输出
P2  886s   if判断和逻辑运算符
...
P5 1211s   指针和malloc      ← 20:11
```

如果给「1:30:00」，脚本会报"超出 P 时长"。**必须先确认是第几 P**。

> 判断方法：B 站播放器右下角有分 P 列表；或者看链接里的 `?p=5`。
> 脚本不做自动跨 P 猜测——猜错了抽出来的帧会张冠李戴，还不如直接报错。

### 4.2 画质：匿名只有 480p，代码小字会糊

实测匿名最高 **640×480**，登录后才有 720p/1080p。

对你的场景（看代码）影响很直接：
- 字号大的板书、IDE 放大过的代码：480p 够用；
- 满屏小字、深色主题细字体：480p 会丢笔画，`1`/`l`、`+`/`t` 分不清。

**建议**：常看的话登录一次（小号），`-Quality 80` 效果差别很大。
登录方式是浏览器取 `SESSDATA` 传给 `-Sessdata`，或用 `dsh-bili-watch` 的扫码面板。

### 4.3 手写体识别有误差，必须标注

我实测同一帧的两种识别结果：

| 真实内容 | 模型看图 | OCR（rapidocr） |
|---|---|---|
| `a = a + 10;` | ✅ 读对 | ❌ `a=a+lo;` |
| `a += 5;` | ✅ 读对 | ❌ `a=ats` |
| `a++;` | ✅ 读对 | ❌ `att;` |
| `printf("%d", a);` | ✅ | ✅ |
| `else if (a>=5){` | ✅ | ⚠️ 括号变全角 |

**结论：代码场景不要靠 OCR，要靠看图。** 但看图也不是 100%，所以笔记里我会：
- 用「⚠️识别存疑」标出不确定处；
- 给回看链接让你一秒核对；
- 代码按 C 语法还原成可编译形式，而不是照抄乱码。

### 4.4 抽帧精度：`-ss` 是"就近关键帧 + 解码到目标点"

ffmpeg 在 `-i` 前放 `-ss` 属于快速定位，误差通常在 1 秒内。
对"这段代码讲了什么"没影响；如果你要卡到某一行代码出现的**精确瞬间**，把时间点往前给 2~3 秒再抽。

## 五之三、分辨率与局部裁剪（实测）

### 登录 vs 匿名

`bili-frame.ps1` 会自动读取 `~/.dsh/bili-watch/credential.json`，有凭证就按登录态取流：

| 项 | 匿名 | 登录 |
|---|---|---|
| 可用轨道 | 4 条（最高 480p） | 8 条（最高 **1080P**） |
| 最高分辨率 | 734×480 | **1654×1080** |
| AI 字幕 | 0 条 | **有**（ai-zh） |
| `-Quality 16/32/64/80` | 全部降级到 480p | 生效 |

> 实测：同一视频同一 P，匿名 `accept_quality` 虽有 80，但 DASH 只返回 16/32；
> 登录后返回 16/32/64/80 全档。

### 分辨率 vs token

| 档位 | 尺寸 | 像素 | 文件 | 估算 token |
|---|---|---:|---:|---:|
| 360p | 640×360 | 230k | 50 KB | ~240 |
| 480p（匿名） | 734×480 | 352k | 70 KB | ~345 |
| 720p | 1102×720 | 793k | — | ~800 |
| 1080p（登录） | 1654×1080 | 1.79M | 259 KB | ~1768 |

### 局部裁剪：同 token 下看得更清

```powershell
# 裁掉顶部 150（浏览器+Colab 工具栏）、底部 130（字幕条）、右侧 420（人脸小窗）
.\bili-frame.ps1 -Video BV1mqrTBvEaf -At 30:00 -Page 7 -Crop "0,150,420,130"
```

同一帧五种方案实测：

| 方案 | 命令 | 尺寸 | 估算 token | 结论 |
|---|---|---|---:|---|
| 整帧 | 默认 | 1654×1080 | 1768 | 含 UI/人脸/字幕，浪费 |
| **裁剪** | `-Crop "0,150,420,130"` | **1234×800** | **975** | ✅ **推荐**，代码完整，省 45% |
| 只裁上下 | `-Crop "0,120,0,80"` | 1654×880 | 1456 | 还行，但右侧人脸窗还在 |
| 裁+放大1.5 | `-Crop "0,150,380,130" -Zoom 1.5` | ~1910×1200 | ~2200 | 字更大，token 翻倍 |
| 裁+放大2 | `-Crop "0,150,420,130" -Zoom 2` | 2468×1760 | 4290 | 没必要 |

**两条原则**：

1. **先裁剪，别急着放大**。放大不会产生新信息，只是把已有像素摊开；
2. 只有源分辨率低（匿名 480p）且字太小，才用 `-Zoom` 补救。

**参数怎么定**：先抽一张整帧量一下 UI 高度，再填 `left,top,right,bottom`。

- 顶部（浏览器标签+地址栏+IDE 工具栏）：130~160
- 底部（字幕条+播放器控制）：100~140
- 右侧（人脸小窗）：380~450
- 左侧（文件树，通常可保留）：0~60

## 六、效率技巧

### 6.1 先粗扫，再精看

不知道代码在哪一分钟时，别一帧帧试。先每 2 分钟抽一帧粗看：

```powershell
.\bili-frame.ps1 -Video BV1HE421j7Lt -At "0:30,2:30,4:30,6:30,8:30" -Page 3 -OutDir .\scan
```

我看完告诉你"代码集中在 4:30 和 6:30 附近"，再精确抽那一分钟内的 3~4 帧。

### 6.2 一次别超过 6 张图

图片很吃上下文。一次抽 4~6 张刚好；要看的更多就分批，避免模型开始"看不清硬猜"。

### 6.3 让字幕和画面互补

- **画面**告诉你"代码长什么样"
- **字幕/口述**告诉你"老师为什么这么写"

两者结合才是完整理解。字幕需要登录（或插件 ASR），见 [02](02-plugin-comparison.md) 的 `dsh-bili-watch`。

### 6.4 顺手记"待查"

每次笔记末尾留三行「没懂的」，比事后回忆有效得多。样例笔记里就有。

| 你想要 | 现在这套够吗 | 需要插件吗 |

1. **先用现在这套**跑两三次，确认工作流顺手；
