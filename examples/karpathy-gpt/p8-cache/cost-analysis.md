- 本文按**空闲时段**算；高峰请 ×2

## 二、30 分钟视频的三种读法

以 30 分钟口播课为例（约 6000 字转写 ≈ 8500 token），图片按 32px patch 的保守估算：

| 读法 | 输入 token | 输出 token | 空闲成本 | 高峰成本 |
|---|---|---|---|---|
| **A. 只看网格定位**（4 张拼图） | 2,340 | 500 | **0.004 元** | 0.008 元 |
| **B. 网格 + ASR 全文**（理解） | 11,340 | 3,000 | **0.023 元** | 0.046 元 |
| **C. 6 张高清单帧 + ASR**（精读） | 17,000 | 3,000 | **0.029 元** | 0.058 元 |
| **D. 预编译索引后逐次追问** | 2,500 / 次 | 800 / 次 | **0.005 元 / 次** | 0.010 元 |

**结论：理解一整节 30 分钟课，大约 2~3 分钱。** 之后每次追问约半分钱。

## 三、P8 实测（42 分 40 秒，比 30 分钟更长的反例）

真实做了一遍，各环节成本：

| 环节 | 实际耗时 | API 成本 |
|---|---|---|
| ASR 全片转写（本地 faster-whisper small） | 229 秒 | **0 元** |
| 抽 23 帧 + 4 张网格（ffmpeg） | ~90 秒 | **0 元** |
| 读 4 张网格 + 归纳结构 | ~30 秒 | 2,340 输入 + ~1,500 输出 = **0.006 元** |
| **一次性预编译合计** | **约 6 分钟** | **< 1 分钱** |

预编译之后，问"RLHF 四个阶段""为什么微调后变笨""RAG 怎么做的"，
都只需**搜一次 ASR 文本 + 至多读 1 帧**：

| 追问类型 | 输入 | 输出 | 成本 |
|---|---|---|---|
| 纯文本事实（搜 ASR 即可） | ~1,500 | ~500 | **0.002 元** |
| 需要看幻灯片（+1 帧裁剪） | ~2,500 | ~800 | **0.005 元** |

## 四、为什么实际花得可能更多

上面的数字是**理想路径**。实际对话里这些会抬高成本：

| 因素 | 影响 |
|---|---|
| **多轮试错** | 抽错时间点、看错帧、重新抽——每轮都重新计费 |
| **长对话累积** | 每轮都要重发历史；上下文越长，输入越大（缓存能缓解） |
| **一次读太多图** | 6 张 1080P 单帧 = 5850 token，比 4 张网格（2340）贵 2.5 倍 |
| **看整帧不裁剪** | 1654×1080 = 1768 token，裁剪后 1234×800 = 975，省 45% |
| **ASR 整片 vs 局部** | 42 分钟全片 229 秒；90 秒局部 9 秒（但 API 成本都是 0） |

本次会话（从第一次问 Karpathy 到现在）的真实消耗远高于单节 3 分钱——
因为做了大量探索：抽了几十张帧、反复试参数、读了很多对比图。
**这是"开发成本"，不是"使用成本"。**

稳定使用后，单节 30 分钟课的成本就是 2~3 分钱量级。

## 五、怎么把成本压到最低

| 做法 | 省什么 |
|---|---|
| 先 `bili-scan` 网格定位，再对单点抽高清 | 图片 token 省 90% |
| 抽帧时裁剪掉 UI/字幕/人脸窗 | 每帧省 45% |
| 用 `bili-find` 定位后再精读，不盲目抽 | 少抽几轮 |
| ASR 只在需要原话时用，且限定区间 | 时间，不是钱 |
| 同一会话内追问，复用上下文 | 缓存命中后输入几乎免费 |
| 避开高峰时段（工作日 9-12、14-18） | 直接省一半 |

## 六、一句话回答

> **看一节 30 分钟的课并理解它，约 3 分钱；
> 做完索引后，每次追问约半分钱。**
> 真正的成本从来不是 API 费用，而是**你为了让它看对地方所花的沟通时间**。
